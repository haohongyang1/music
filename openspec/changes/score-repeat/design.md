## Context

吉他六线谱的反复记号主要有：

- **小反复（Repeat）**: `||:` 和 `:||` 标记，通常重复 2 次
- **多段反复**: 1st/2nd endings（第一结尾/第二结尾）
- **跳跃反复**: D.C.（从头）、D.S.（从记号）、Fine（结束）

本功能先实现**小反复**，是最常见的场景。

## Goals / Non-Goals

**Goals:**
- 支持小反复记号的段落循环播放
- 显示当前段落和重复进度（如 "A段 (2/3)"）
- 提供「跳过反复」选项
- 向后兼容未标记的乐谱

**Non-Goals:**
- 自动识别乐谱中的反复记号（采用手动标注）
- 多段反复（1st/2nd endings）
- 跳跃反复（D.C./D.S.）
- 音频节拍同步

## Decisions

### 数据结构设计

在 `scoreData.js` 中为每首乐谱添加：

```js
{
  // ... 现有字段
  sections: [
    { id: 'intro', name: '前奏', startPos: 0, endPos: 180 },
    { id: 'verse-a', name: 'A段', startPos: 180, endPos: 540 },
    { id: 'chorus', name: '副歌', startPos: 540, endPos: 840 },
  ],
  repeats: [
    {
      type: 'segment',           // 小反复类型
      fromSection: 'verse-a',    // 起始段落
      toSection: 'verse-a',      // 回到段落起点
      times: 2                   // 总播放次数
    }
  ]
}
```

**Why:**
- `startPos` / `endPos` 使用像素值，与现有滚动逻辑一致
- 段落 ID 支持反复规则引用
- `times` 表示总播放次数（含首次）

### 播放状态机

```
┌──────────────┐
│ 开始播放     │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 获取当前段落   │
└──────┬───────┘
       │
       ▼
┌──────────────┐
│ 检查是否到达   │
│ 反复触发点     │
└──────┬───────┘
       │
   ┌───┴───┐
   │ No    │ Yes
   ▼       ▼
继续播放  检查重复次数
           │
      ┌────┴────┐
      │ 未完成   │ 已完成
      ▼         ▼
   跳转回起点   标记已播放
                 │
                 ▼
             检查后续规则
```

**Why:**
- 状态机清晰处理反复、跳过、完成等状态
- 便于后续扩展（如 D.C./D.S.）

### 段落位置计算

使用图片高度和页面布局来推算段落位置：

```js
// 段落位置 = 页面偏移 + 页内像素位置
// 例如：第2页开头 300px 处
startPos: (pageIndex * pageHeight) + 300
```

**Why:**
- 与现有 `setScoreOffset` 逻辑一致
- 响应式布局下保持相对位置

### UI 设计

播放控制栏上方显示段落状态：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  A段 (2/3) → B段   [跳过反复]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Why:**
- 段落名称让用户知道当前位置
- 次数显示播放进度
- 跳过反复按钮方便完整播放

**Alternative considered:** 仅在到达反复点时提示。Rejected，用户需要知道当前段落。

### 向后兼容

没有 `sections` 字段的乐谱保持原有线性播放。

**Why:**
- 不影响现有乐谱使用
- 可渐进式添加反复标记

## Risks / Trade-offs

- **段落位置手动标注**：替换图片后需要更新。Mitigation: 集中管理，更新明显。
- **跨段反复**：当前设计支持段内反复，跨段反复可扩展。Mitigation: 数据结构已预留扩展空间。
- **复杂乐谱**：多层反复嵌套较难标注。Mitigation: 先解决单层反复，复杂场景后续扩展。
